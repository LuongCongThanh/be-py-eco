Xử lý lỗi kiểu Python: except phải chỉ rõ loại, và with để dọn dẹp tự động

Điểm khác với try/catch quen thuộc: except phải nêu rõ loại lỗi, và with là khối riêng để đảm bảo resource luôn được dọn dẹp.

1. try / except: phải chỉ rõ loại lỗi

Cái bạn quen dùng

try {
  result = 10 / 0;
} catch (e) {
  print(e);
}

Python

try:
    result = 10 / 0
except ZeroDivisionError:
    print("khong the chia cho 0")
# -> in ra: khong the chia cho 0

Bắt đúng loại lỗi giúp chỉ "nuốt" đúng thứ mình lường trước, còn bug thật (lỗi lạ) vẫn được ném lên chứ không bị giấu đi.

try:
    so = int("abc")
except ZeroDivisionError:
    print("khong toi day")
# -> ValueError: invalid literal for int() with base 10: 'abc'
# (loi khong khop except nao thi van duoc nem tiep len tren,
#  khong bi "nuot" mat)
Python muốn bạn khai báo rõ mình đang bắt lỗi gì (ZeroDivisionError, ValueError, ...) — bắt một exception mơ hồ, không rõ loại, dễ che giấu bug thật. Có thể liệt kê nhiều loại: except (ValueError, TypeError) as e:. Viết except: trống (không tên) là bắt luôn cả KeyboardInterrupt (Ctrl+C) — chương trình sẽ "không chịu tắt" được nữa, nên gần như không bao giờ nên dùng.

2. else và finally — tùy chọn, thêm sắc thái

try:
    result = 10 / 2
except ZeroDivisionError:
    print("loi")
else:
    print("chi chay neu KHONG co loi")   # result = 5.0, in ra dong nay
finally:
    print("luon chay du co loi hay khong")
# -> in ra:
# chi chay neu KHONG co loi
# luon chay du co loi hay khong

else tách "code xử lý kết quả" ra khỏi khối try, để nó không bị except bắt nhầm nếu lỡ ném lỗi.

3. Tự ném lỗi bằng raise

def divide(a, b):
    if b == 0:
        raise ValueError("b khong duoc bang 0")
    return a / b

divide(10, 0)
# -> ValueError: b khong duoc bang 0

Có thể ném lại (re-raise) đúng lỗi vừa bắt để log rồi vẫn để lỗi lan lên trên:

try:
    divide(10, 0)
except ValueError as e:
    print(f"da ghi log: {e}")
    raise   # khong truyen gi cho raise -> nem lai dung loi cu
# -> in ra: da ghi log: b khong duoc bang 0
# -> sau do chuong trinh van dung vi ValueError duoc nem lai

4. with: dọn dẹp resource, không cần finally thủ công

with open("file.txt") as f:
    content = f.read()
# file tu dong duoc dong khi ra khoi block "with",
# ke ca khi co loi xay ra ben trong

Không có with, bạn phải tự viết:

f = open("file.txt")
try:
    content = f.read()
finally:
    f.close()   # de quen dong nay se ro ri file handle
with dùng được cho bất kỳ thứ gì implement giao thức "context manager" — kết nối DB, transaction, lock, v.v. Ví dụ, transaction.atomic() trong Django chính là một context manager.

5. Vì sao with hoạt động được: __enter__ / __exit__

with dựa trên giao ước (protocol): object nào có __enter__ và __exit__ đều dùng được. Python luôn gọi __exit__ khi ra khỏi block — kể cả khi có lỗi.

class KetNoiGia:
    def __enter__(self):
        print("mo ket noi")
        return self
    def __exit__(self, exc_type, exc_value, traceback):
        print("dong ket noi")
        return False   # False = khong nuot loi, de loi tiep tuc nem len

with KetNoiGia() as k:
    print("dang dung ket noi")
    raise ValueError("loi trong luc dung")
# -> mo ket noi
# -> dang dung ket noi
# -> dong ket noi          (van chay du co loi!)
# -> ValueError: loi trong luc dung   (loi van duoc nem tiep)

Cách viết gọn hơn cho cùng ý tưởng là dùng decorator @contextmanager từ module contextlib — hàm chỉ cần yield đúng một lần, phần trước yield là "enter", phần sau (thường trong finally) là "exit".

from contextlib import contextmanager

@contextmanager
def ket_noi_gia():
    print("mo ket noi")
    try:
        yield "ket-noi-so-1"
    finally:
        print("dong ket noi")

with ket_noi_gia() as k:
    print(f"dang dung: {k}")
# -> mo ket noi
# -> dang dung: ket-noi-so-1
# -> dong ket noi
