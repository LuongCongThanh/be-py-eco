Module & Decorator: nền tảng cuối cùng trước khi vào Django

Đây là bài cuối của giai đoạn 1 — sau bài này bạn sẽ có đủ vốn Python cốt lõi để bắt đầu đọc code thật trong be-py-eco (xem MISSION.md).

1. Module: mỗi file .py là một module

Trong Python, bất kỳ file .py nào cũng tự động là một module — tên module chính là tên file (bỏ đuôi .py). import math tìm file đó, chạy một lần, rồi gán namespace của nó vào biến math.

import math
math.sqrt(16)               # -> 4.0
math.pi                      # -> 3.141592653589793

from math import sqrt
sqrt(16)                     # -> 4.0 (dùng thẳng, không cần tiền tố math.)

from math import sqrt as can_bac_hai
can_bac_hai(16)              # -> 4.0 (đổi tên lúc import, tránh trùng tên)

Vì sao có 2 cách import? import math giữ tiền tố math. (rõ nguồn gốc, ít đụng tên); from math import sqrt gọn hơn nhưng dễ trùng tên. Dùng cách đầu khi cần nhiều hàm, cách sau khi chỉ cần 1-2 cái.

Trong be-py-eco, cấu trúc thư mục ánh xạ trực tiếp vào câu import — đường dẫn file quyết định "đường dẫn import":

# src/modules/foo/models.py
from django.db import models
from common.db import BaseModel   # tương ứng src/common/db.py
# -> Python đi tìm package "common", rồi module "db" bên trong nó,
#    rồi lấy tên "BaseModel" từ đó ra.
Vì sao module chỉ chạy 1 lần? Python cache module đã import vào sys.modules. Nếu 5 file khác nhau đều import common.db, Python chỉ thực thi file db.py ở lần import đầu tiên, các lần sau chỉ lấy lại kết quả đã cache. Đây là lý do code ở top-level của một module (ví dụ mở kết nối DB, đọc config) chỉ chạy đúng 1 lần dù được import ở nhiều nơi — khác với việc "gọi hàm" thông thường sẽ chạy lại mỗi lần gọi.

2. Decorator: hàm bọc quanh hàm khác

Trong Python, hàm là một giá trị (first-class object) — gán, truyền, trả về được như số hay chuỗi. Decorator là một hàm nhận vào một hàm khác và trả về một hàm mới thay thế hàm gốc.

Ý tưởng tổng quát

// "wrap" mot ham — pattern quen thuoc
function greet(name) {
  return "hello, " + name;
}
greet = logWrapper(greet);
// goi greet(...) gio day chay qua ham bao ngoai truoc

Python — cú pháp @

@log_call
def greet(name):
    return f"hello, {name}"
# hoan toan tuong duong voi:
# def greet(name): ...
# greet = log_call(greet)
def log_call(func):
    def wrapper(*args, **kwargs):
        print(f"goi {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@log_call
def greet(name):
    return f"hello, {name}"

greet("Lan")
# in ra: "goi greet"
# tra ve: "hello, Lan"

@log_call
def add(a, b):
    return a + b

add(2, 3)
# in ra: "goi add"
# tra ve: 5
@log_call phía trên def greet chỉ là cú pháp gọn cho greet = log_call(greet). Decorator nhận vào một hàm, trả về một hàm khác đã được "bọc" thêm hành vi — mà không phải sửa code bên trong hàm gốc.

3. Vì sao wrapper(*args, **kwargs) lại cần thiết

log_call viết một lần nhưng phải hoạt động cho mọi hàm nó bọc, dù mỗi hàm nhận số tham số khác nhau — nên wrapper phải nhận bất kỳ thứ gì rồi chuyển tiếp nguyên vẹn:

def log_call(func):
    def wrapper(*args, **kwargs):
        # args: tuple chua cac tham so vi tri, vd (2, 3)
        # kwargs: dict chua cac tham so tu khoa, vd {"c": 1}
        print(f"goi {func.__name__} voi args={args}, kwargs={kwargs}")
        return func(*args, **kwargs)   # "mo goi" lai, chuyen tiep nguyen ven
    return wrapper

Viết cứng def wrapper(a, b) sẽ hỏng ngay với greet(name); *args, **kwargs giữ cho decorator tổng quát với mọi chữ ký hàm.

Closure: wrapper "nhớ" biến func của lần gọi log_call đó, kể cả sau khi log_call đã chạy xong — mỗi hàm decorate giữ đúng tham chiếu của riêng nó.

4. Vì sao bài này quan trọng cho Django/DRF

@api_view(["GET"])
def my_view(request):
    ...
    # -> Django chi cho phep GET; goi voi POST se tra ve 405
    #    truoc khi ham my_view thuc su chay

@login_required
def my_view(request):
    ...
    # -> neu chua dang nhap, redirect sang trang login;
    #    my_view chi chay khi da xac thuc

Django/DRF dùng @... phía trên view để thêm hành vi — giới hạn HTTP method, kiểm tra đăng nhập, cache. Không phải "ma thuật": chỉ là một hàm bọc view gốc bằng logic kiểm tra thêm.
