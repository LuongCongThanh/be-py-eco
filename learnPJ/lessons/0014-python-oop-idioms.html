Bài 14 · Python cốt lõi (bổ sung)

OOP idiom đặc thù của Python — không dạy lại "OOP là gì"

Bài này không dạy lại OOP cơ bản (đã ở bài 4) — chỉ lấp chỗ Python làm khác hẳn ngôn ngữ khác, và vì sao.

1. Encapsulation ở Python: quy ước, không phải từ khóa

Cái bạn quen dùng

private int balance;
public int getBalance() {...}

Python

class Account:
    def __init__(self, balance):
        self._balance = balance
Python không có private/ public thật sự — mọi thuộc tính đều truy cập được từ bên ngoài. Một dấu gạch dưới (_balance) chỉ là quy ước "đây là internal, đừng đụng vào" — Python không ép buộc gì cả, dựa hoàn toàn vào sự tự giác của người đọc code (triết lý "we're all consenting adults here" — Python tin rằng lập trình viên đủ trưởng thành để tự tuân thủ quy ước, thay vì cần trình biên dịch canh gác).

Lý do: Python ưu tiên introspect linh hoạt (debug, test, ORM như Django/DRF) — private cứng sẽ cản trở việc đó.

class Account:
    def __init__(self, balance):
        self._balance = balance   # quy uoc: "internal, dung dung vao"

acc = Account(100)
print(acc._balance)     # 100 — van truy cap duoc binh thuong, KHONG loi
acc._balance = 999       # van gan duoc binh thuong, Python khong ngan

2. Name mangling: __secret khác _secret thế nào

2 dấu gạch dưới ở đầu (self.__secret) kích hoạt name mangling: Python tự đổi tên thành _TenClass__secret — để tránh đụng tên khi kế thừa, không phải để bảo mật.

class Account:
    def __init__(self, balance):
        self.__secret = "ma-pin"   # se bi doi ten ngam thanh _Account__secret

acc = Account(100)
print(acc.__secret)
# AttributeError: 'Account' object has no attribute '__secret'
# (vi thuoc tinh that su ten la _Account__secret, khong phai __secret)

print(acc._Account__secret)
# "ma-pin"  — van truy cap duoc neu biet ten that su sau khi mangle
Name mangling gây khó truy cập nhầm hơn (bạn phải cố tình gõ đúng _TenClass__ten) chứ hoàn toàn không phải bảo mật thật — ai đọc code cũng đoán được quy tắc đổi tên và truy cập bình thường. Trong thực tế, quy ước phổ biến ở Python là dùng 1 dấu gạch dưới (_balance) cho "internal, đừng đụng"; 2 dấu gạch dưới chỉ dùng khi thật sự cần tránh đụng tên lúc kế thừa nhiều tầng.

3. @property: method trông như thuộc tính

@property cho phép thêm logic tính toán/validate sau này mà không phá code nơi khác đang gọi obj.radius.

class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def area(self):
        return 3.14159 * self.radius ** 2

c = Circle(2)
print(c.area)     # 12.56636 — KHONG can dau ngoac ()
c.radius = 3
print(c.area)     # 28.27431 — tinh lai moi lan truy cap, khong luu san

Là decorator (bài 7), tính lại mỗi lần truy cập nhưng gọi như thuộc tính. Có thể thêm @radius.setter để validate khi gán:

class Circle:
    def __init__(self, radius):
        self.radius = radius

    @property
    def radius(self):
        return self._radius

    @radius.setter
    def radius(self, value):
        if value <= 0:
            raise ValueError("radius phai duong")
        self._radius = value

c = Circle(5)
c.radius = -1
# ValueError: radius phai duong — validate xay ra ngay khi gan, tu dong

4. @classmethod / @staticmethod

class Book:
    def __init__(self, title):
        self.title = title

    @classmethod
    def from_string(cls, raw):
        return cls(raw.strip().title())   # constructor phu

    @staticmethod
    def is_valid_title(title):
        return len(title) > 0              # khong dung self/cls o day

b = Book.from_string("  the great gatsby  ")
print(b.title)                    # "The Great Gatsby"
print(Book.is_valid_title(""))    # False

@classmethod nhận cls thay self — dùng làm constructor phụ (factory) khi cần nhiều cách khởi tạo. @staticmethod chỉ là hàm thường nhét vào class cho gọn namespace, không cần self/cls.

5. Dunder methods khác ngoài __init__

class Book:
    def __init__(self, title):
        self.title = title

    def __str__(self):
        return f"Book: {self.title}"     # print(book) goi ham nay

    def __eq__(self, other):
        return self.title == other.title  # book1 == book2 goi ham nay

print(Book("A"))          # "Book: A"
print(Book("A") == Book("A"))     # True — vi da dinh nghia __eq__
Không định nghĩa __eq__, toán tử == giữa 2 object sẽ so sánh identity (có phải cùng object trong bộ nhớ không) — giống is, không so sánh nội dung bên trong. Đây là bẫy phổ biến khi mới quen Python. 
class Book:
    def __init__(self, title):
        self.title = title
    # khong dinh nghia __eq__

b1 = Book("A")
b2 = Book("A")
print(b1 == b2)   # False — 2 object khac nhau trong bo nho, du title giong nhau
print(b1 == b1)   # True — cung 1 object

Mọi kiểu built-in (int, list...) cũng hoạt động qua cùng cơ chế dunder này — 1 == 1 thực chất gọi (1).__eq__(1). Class của bạn chỉ đang hòa nhập vào hệ thống chung, không phải cơ chế riêng.

6. Polymorphism ở Python: thường qua duck typing, không phải interface

Duck typing (bài 5) là cách Python đạt polymorphism: không cần interface khai báo trước, chỉ cần object có method cần gọi — kiểm tra lúc chạy, không phải lúc biên dịch.

class Dog:
    def speak(self):
        return "Woof"

class Duck:
    def speak(self):
        return "Quack"

def make_it_speak(animal):
    return animal.speak()   # khong quan tam animal la class gi,
                             # chi can co method speak()

print(make_it_speak(Dog()))   # "Woof"
print(make_it_speak(Duck()))  # "Quack" — Dog va Duck khong he co chung base class

Module abc có thể ép class con phải implement method nếu thật sự cần — nhưng là tùy chọn, không phải mặc định.
