Function trong Python: không khai báo kiểu, "trả về nhiều giá trị"

Function ở Python không khai báo kiểu tham số/trả về, và "trả về nhiều giá trị" thực chất chỉ là unpacking — cơ chế bạn đã gặp ở bài 2.

1. Định nghĩa hàm với def

Cái bạn quen dùng

String greet(String name) {
  return "hello, " + name;
}

Python

def greet(name):
    return f"hello, {name}!"

print(greet("Lan"))
# -> hello, Lan!

Thân hàm là block thụt lề, không có kiểu bắt buộc. name chỉ là tên tạm trỏ tới giá trị bất kỳ; Python chỉ báo lỗi khi thân hàm dùng sai giá trị đó — đây là "duck typing".

2. Giá trị mặc định cho tham số

def greet(name, greeting="hello"):
    return f"{greeting}, {name}!"

greet("world")                  # -> "hello, world!"
greet("world", "hi")            # -> "hi, world!"
greet("world", greeting="yo")   # -> "yo, world!"  (gọi bằng tên tham số)

Gọi bằng tên tham số (keyword argument) giúp code tự giải thích, ví dụ resize(width=800, height=600) rõ hơn resize(800, 600).

Bẫy hay gặp: đừng dùng list/dict làm giá trị mặc định — def f(items=[]) — vì nó chỉ được tạo một lần lúc def chạy rồi dùng lại cho mọi lần gọi, nên sửa list sẽ "rò rỉ" sang lần gọi sau. An toàn hơn: def f(items=None): items = items or [].

3. "Trả về nhiều giá trị" — thực chất là một tuple

def min_max(numbers):
    return min(numbers), max(numbers)

result = min_max([3, 1, 4, 1, 5])
print(result)          # -> (1, 5)
print(type(result))    # -> <class 'tuple'>

lo, hi = min_max([3, 1, 4, 1, 5])
print(lo, hi)           # -> 1 5
Một hàm Python luôn trả về đúng một giá trị: return a, b chỉ là cách viết tắt gói a, b vào tuple (a, b). Rồi lo, hi = ... unpack tuple đó ra 2 biến (giống enumerate() ở bài 2). Quên unpack thì bạn nhận nguyên tuple, không phải hai biến riêng.

4. Unpacking không chỉ dùng với hàm

point = (3, 4)
x, y = point                  # x = 3, y = 4
print(f"{x}, {y}")             # -> 3, 4

first, *rest = [1, 2, 3, 4]
print(first)                   # -> 1
print(rest)                    # -> [2, 3, 4]

a, *_, last = [1, 2, 3, 4, 5]
print(a, last)                 # -> 1 5

*rest gom "phần còn lại" vào một list. *_ là quy ước đặt tên cho "phần bỏ qua, không dùng tới".

5. Vì sao unpacking sai số lượng lại báo lỗi ngay?

x, y = (1, 2, 3)
# -> ValueError: too many values to unpack (expected 2)

Chủ đích thiết kế: số biến bên trái phải khớp chính xác số phần tử bên phải (trừ khi có *rest). Đây là lớp bảo vệ duy nhất chống lỗi "hàm trả về 3 giá trị nhưng chỗ gọi tưởng chỉ có 2".

6. Gợi ý kiểu (type hints) — tùy chọn, chỉ để tài liệu hóa

def greet(name: str, greeting: str = "hello") -> str:
    return f"{greeting}, {name}!"

greet(123, "hi")   # vẫn chạy được, in ra "hi, 123!" — Python không chặn

Python không kiểm tra hint lúc chạy — chúng chỉ giúp người đọc và công cụ như mypy bắt lỗi sớm (xem uv run python -m mypy src trong how-to-run.md).
