Duck typing: quan tâm hành vi, không quan tâm khai báo kiểu

Python không có khái niệm interface bắt buộc như nhiều ngôn ngữ khác, và dùng sâu hơn dict/set.

1. Duck typing là gì, và vì sao Python làm vậy

Ngôn ngữ static typing (Java, C#, TypeScript...) bắt các class khai báo rõ mình implement interface nào, rồi compiler kiểm tra trước khi chạy. Python bỏ qua bước đó: khi gọi animal.speak(), nó chỉ hỏi "object này có method speak không?" ngay tại thời điểm gọi.

def make_it_speak(animal):
    return animal.speak()

class Dog:
    def speak(self): return "woof"

class Duck:
    def speak(self): return "quack"

make_it_speak(Dog())    # -> "woof"
make_it_speak(Duck())   # -> "quack"

class Robot:
    def speak(self): return "beep boop"

make_it_speak(Robot())  # -> "beep boop" — Robot không liên quan gì tới Dog/Duck,
                         # không kế thừa chung class nào, vẫn chạy được
"If it walks like a duck and quacks like a duck, it's a duck." — make_it_speak không kiểm tra animal là Dog hay Duck, cũng không cần cả hai class cùng implement một interface khai báo trước. Miễn là object có method speak(), hàm chạy được.

Hệ quả: Python không báo lỗi thiếu method trước — lỗi chỉ lộ ra khi dòng code đó thực sự chạy:

class Cat:
    pass  # quên định nghĩa speak()

make_it_speak(Cat())
# -> AttributeError: 'Cat' object has no attribute 'speak'
# (lỗi này chỉ xảy ra khi gọi make_it_speak(Cat()), không phải khi định nghĩa Cat)

Ngôn ngữ static typing

Bắt khai báo implements ISpeaker; compiler chặn lỗi thiếu method trước khi chạy.

Python (duck typing)

Không cần khai báo; linh hoạt hơn nhưng lỗi thiếu method chỉ lộ ra lúc chạy.

2. dict: truy cập, thêm, kiểm tra tồn tại

dict lưu dữ liệu dạng key → value, giống Map/HashMap ở ngôn ngữ khác — nhưng giữ nguyên thứ tự chèn (từ Python 3.7+).

person = {"name": "Lan", "age": 25}

person["name"]              # -> "Lan"
person["job"]               # -> KeyError: 'job'  (key không tồn tại!)
person.get("job", "n/a")    # -> "n/a" — không lỗi nếu thiếu key
person.get("job")           # -> None  (mặc định của .get() là None nếu không truyền default)
person["job"] = "engineer"  # thêm key mới (dict cho phép sửa — mutable)
person["age"] = 26           # sửa giá trị key đã có
"age" in person              # -> True
"salary" in person            # -> False

Quy tắc chọn: dùng [] khi chắc chắn key phải có (thiếu là bug); dùng .get() khi thiếu key là chuyện bình thường.

3. Lặp qua dict

for key, value in person.items():
    print(key, value)
# -> name Lan
# -> age 26
# -> job engineer

for key in person:            # lặp mặc định chỉ cho key, không cần .keys()
    print(key)
# -> name
# -> age
# -> job

for key, value in ... lại là unpacking (bài 3): .items() trả từng cặp (key, value), giống enumerate().

4. Dict comprehension — cùng ý tưởng với list comprehension (bài 2)

squares = {x: x * x for x in range(5)}
# -> {0: 0, 1: 1, 2: 4, 3: 9, 4: 16}

# Ví dụ thực tế hơn: đảo ngược key/value
prices = {"apple": 3, "banana": 1}
by_price = {v: k for k, v in prices.items()}
# -> {3: "apple", 1: "banana"}

5. set: tập hợp, phép toán tập hợp

set là tập hợp phần tử duy nhất, không thứ tự, dùng cùng cơ chế hash như dict. Nhờ vậy kiểm tra "X có trong set" gần như tức thời (O(1)), còn "X có trong list" phải quét từng phần tử (O(n)).

a = {1, 2, 3}
b = {2, 3, 4}

a | b   # hợp:  -> {1, 2, 3, 4}
a & b   # giao: -> {2, 3}
a - b   # hiệu: -> {1}

# Loại trùng lặp từ 1 danh sách
names = ["Lan", "Huy", "Lan", "Mai", "Huy"]
unique_names = set(names)
# -> {"Lan", "Huy", "Mai"}  (thứ tự có thể khác, set không giữ thứ tự chèn)

3 in a          # -> True, gần như tức thời dù a có bao nhiêu phần tử
3 in [1, 2, 3]  # -> True nhưng phải quét list từ đầu tới khi thấy 3

Lưu ý: {} rỗng tạo ra dict rỗng, không phải set rỗng (vì dict ra đời trước và chiếm cú pháp đó) — muốn set rỗng phải viết set().

type({})     # -> <class 'dict'>
type(set())  # -> <class 'set'>
