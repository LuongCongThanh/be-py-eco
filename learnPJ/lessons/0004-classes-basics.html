Class trong Python: không có new, và self luôn tường minh

Điểm khác với OOP bạn đã biết: tạo object không cần new, và "con trỏ tới chính object" (this ở nơi khác) phải khai báo tường minh làm tham số đầu tiên của mọi method.

1. Định nghĩa class

Cái bạn quen dùng

class Dog {
  String name;
  Dog(String name) {
    this.name = name;
  }
  String bark() {
    return name + " says woof!";
  }
}

Python

class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f"{self.name} says woof!"

Không khai báo kiểu, không dấu ngoặc nhọn — khối lệnh xác định bằng thụt đầu dòng. Thuộc tính name chỉ xuất hiện khi __init__ gán nó vào self.

2. Tạo object — không có new

rex = Dog("Rex")
print(rex.bark())      # -> Rex says woof!
print(type(rex))       # -> <class '__main__.Dog'>
print(rex is Dog("Rex"))  # -> False (hai object khác nhau, dù cùng name)

Gọi tên class như gọi hàm (Dog("Rex")) là đủ để tạo object mới, vì class tự nó là một object gọi được (callable) — nó tự tạo instance rồi gọi __init__ lên instance đó.

3. self: luôn là tham số đầu tiên, luôn tường minh

Ở nhiều ngôn ngữ, this được ngầm định có sẵn bên trong method. Ở Python, self phải được khai báo tường minh làm tham số đầu tiên của mọi method (def bark(self):) — nhưng khi gọi (rex.bark()), bạn không truyền nó, Python tự truyền vào giúp bạn.

Một method chỉ là hàm bình thường gắn vào class: rex.bark() là cách viết gọn của Dog.bark(rex). Kiểm chứng:

print(rex.bark())        # -> Rex says woof!
print(Dog.bark(rex))     # -> Rex says woof! (y hệt, gọi tường minh qua class)

self chỉ là tham số đầu tiên, nhận giá trị tự động khi gọi qua object.method() — tên gọi là quy ước, không phải từ khóa bắt buộc, nhưng ai cũng dùng self.

4. __init__: hàm khởi tạo

class Dog:
    def __init__(self, name):
        self.name = name   # gán thuộc tính cho object

rex = Dog("Rex")
print(rex.name)   # -> Rex

Tên 2 gạch dưới đầu-cuối gọi là "dunder method" — hook đặc biệt Python tự gọi. __init__ chạy ngay sau khi object đã được tạo, chỉ để thiết lập trạng thái ban đầu, không phải để tạo object.

5. Kế thừa vẫn dùng ngoặc đơn, không có extends

class Puppy(Dog):
    def bark(self):
        return f"{self.name} says yip!"   # override

p = Puppy("Miu")
print(p.bark())          # -> Miu says yip! (dùng bản override của Puppy)
print(isinstance(p, Dog))  # -> True (Puppy vẫn là một loại Dog)

Puppy(Dog) nghĩa là kế thừa từ Dog — ngoặc đơn đóng vai trò extends. Muốn thêm logic khởi tạo riêng mà vẫn tận dụng Dog, gọi tường minh qua super():

class Puppy(Dog):
    def __init__(self, name, age_months):
        super().__init__(name)   # chạy __init__ của Dog trước
        self.age_months = age_months

p = Puppy("Miu", 3)
print(p.name, p.age_months)   # -> Miu 3

6. Vì sao dễ nhầm với ngôn ngữ khác: method không "thuộc về" instance như bạn nghĩ

Method sống trên class, không phải trên từng instance — mỗi object chỉ giữ dữ liệu riêng (self.name), code method dùng chung. Quên viết self khi định nghĩa method là lỗi rất hay gặp khi mới chuyển sang Python.
