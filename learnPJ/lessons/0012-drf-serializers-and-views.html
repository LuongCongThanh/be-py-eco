Serializer & View: nơi request thật sự được xử lý

Cũng như bài 11: src/common/api/ trong be-py-eco hiện gần như rỗng — dự án ở Slice 0. Bài này dạy khái niệm DRF tổng quát, để bạn sẵn sàng đọc/viết code khi serializer và view thật xuất hiện ở các slice sau.

1. Vì sao cần serializer? Bài toán mà nó giải quyết

HTTP chỉ mang được text (JSON); model Django (bài 11) là object Python. Serializer là lớp trung gian dịch hai chiều: model → dict/JSON (trả response) và JSON → dict đã validate → model (nhận request, có kiểm tra dữ liệu client gửi lên).

from rest_framework import serializers

class BookSerializer(serializers.ModelSerializer):
    class Meta:
        model = Book
        fields = ["id", "title", "author", "available"]

class Meta: vẫn là class Python bình thường (bài 4) — DRF đọc Meta.model/Meta.fields để biết serialize field nào.

2. ModelSerializer vs Serializer thường

ModelSerializer tự sinh field/validation từ model (giới hạn max_length... lấy thẳng từ field model). Còn serializers.Serializer bắt khai tay từng field:

class BookSerializer(serializers.Serializer):
    id = serializers.IntegerField(read_only=True)
    title = serializers.CharField(max_length=200)
    author = serializers.CharField(max_length=100)
    available = serializers.BooleanField()

Dùng bản thường khi dữ liệu không khớp 1-1 với 1 model; với CRUD đơn giản (phổ biến nhất) thì ModelSerializer là mặc định.

3. Hai chiều: serialize (ra JSON) và deserialize (vào model)

# Model -> JSON (vi du: tra response cho GET)
serializer = BookSerializer(book_instance)
serializer.data
# {"id": 7, "title": "Dune", "author": "Frank Herbert", "available": true}

# JSON -> Model, co validate (vi du: nhan du lieu tu POST)
serializer = BookSerializer(data=request.data)
serializer.is_valid()         # True/False, khong raise
serializer.validated_data      # dict da lam sach (bai 5)
serializer.save()               # tao/cap nhat trong DB
Để ý: DRF chọn kiểm tra tường minh (if serializer.is_valid():) thay vì bắt try/except (bài 6) cho lỗi validate đầu vào — lỗi "dữ liệu client sai" dùng kiểm tra có điều kiện, lỗi hệ thống thật mới dùng exception.

4. Trace end-to-end: 1 request POST đi qua serializer

POST /api/v1/books/
{"title": "Dune", "author": "", "available": true}

# request.data la dict Django da parse tu JSON tren
serializer = BookSerializer(data=request.data)
serializer.is_valid()      # -> False: "author" rong ma bat buoc
serializer.errors
# {"author": ["This field may not be blank."]}
# View tra thang dict nay ra client voi status 400

# Client sua lai va gui dung:
serializer = BookSerializer(data={"title": "Dune", "author": "Frank Herbert", "available": True})
serializer.is_valid()          # -> True
serializer.validated_data      # dict da lam sach, dung noi bo
book = serializer.save()       # tao dong moi trong bang Book -> tra ve Book instance
serializer.data
# {"id": 8, "title": "Dune", "author": "Frank Herbert", "available": true}
# co them "id" vi gio serializer dang serialize object "book" vua tao, khong phai dict input

serializer.save() tự quyết định tạo mới hay cập nhật: không kèm instance có sẵn (như trên) → Model.objects.create(...); có instance (BookSerializer(book, data=request.data)) → cập nhật instance đó.

5. APIView: mỗi HTTP method = 1 method cùng tên trong class

from rest_framework.views import APIView
from rest_framework.response import Response

class BookListView(APIView):
    def get(self, request):
        books = Book.objects.all()
        serializer = BookSerializer(books, many=True)   # many=True: serialize ca list
        return Response(serializer.data)

    def post(self, request):
        serializer = BookSerializer(data=request.data)
        if serializer.is_valid():
            serializer.save()
            return Response(serializer.data, status=201)
        return Response(serializer.errors, status=400)

GET → gọi get(self, request); POST → gọi post(self, request) (self là instance của BookListView, bài 4) — đúng luồng POST đã trace ở mục 4. many=True báo serializer đầu vào là queryset, trả về list JSON.

6. Đăng ký vào urls.py

from django.urls import path
urlpatterns = [
    path("api/v1/books/", BookListView.as_view()),
]

.as_view() chuyển class thành function Django hiểu được, nối vào urlpatterns (bài 10) — khép kín luồng: request → urlpatterns → as_view() → dispatch tới post() → serializer validate/save → Response.
