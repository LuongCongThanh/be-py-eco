Bài 9 · Giai đoạn 2 — Django/DRF trong be-py-eco

Settings của Django là gì — giải mã lệnh bạn đã gõ ở how-to-run.md

Bắt đầu giai đoạn 2. Trước khi chạm view hay model, giải mã dòng lệnh bạn đã gõ khi setup project:

$env:DJANGO_SETTINGS_MODULE = "config.settings.local"

Dùng file thật trong repo be-py-eco.

1. Settings chỉ là một file .py bình thường

# src/config/settings/base.py
SECRET_KEY = env("SECRET_KEY")
DEBUG = env.bool("DEBUG", default=False)
DATABASES = {"default": env.db_url("DATABASE_URL")}

SECRET_KEY, DEBUG, DATABASES chỉ là biến toàn cục trong module base.py — Django import module này như mọi module Python khác rồi đọc thuộc tính theo tên. Gõ sai tên (ví dụ SECRETKEY) không báo lỗi cú pháp, chỉ khiến Django không tìm thấy biến và dùng mặc định hoặc báo thiếu cấu hình.

Thiết kế "biến toàn cục trong module" (thay vì class/dict) cho phép dùng thẳng from .base import * để "thừa kế" giữa các file môi trường — xem mục 3. Đổi lại là không có kiểm tra kiểu tự động; bù bằng django-environ (mục 5) và manage.py check.

2. DJANGO_SETTINGS_MODULE: đường dẫn dotted tới file đó

Đường dẫn file

src/config/settings/local.py

Dotted path Django cần

config.settings.local

Django không tự biết dùng file nào trong 4 file (base/local/test/production) — biến môi trường DJANGO_SETTINGS_MODULE trả lời câu hỏi đó, tương đương cú pháp import config.settings.local.

Dùng biến môi trường (thay vì tham số dòng lệnh) vì mọi công cụ Django (dev server, Celery, test runner, WSGI) cần biết cùng settings module dù khởi động khác cách nhau — set một lần, mọi tool con đều đọc được. Đó là lý do manage.py/wsgi.py đều gọi os.environ.setdefault(...): ưu tiên giá trị bạn set từ ngoài, chỉ dùng mặc định nếu chưa set.

3. 4 file settings không tách biệt — chúng "kế thừa" nhau

# src/config/settings/local.py
from .base import *   # lay toan bo bien tu base.py

DEBUG = True           # roi ghi de rieng 1 bien
from .base import * đưa toàn bộ biến của base.py (SECRET_KEY, DATABASES, CACHES, ...) vào local.py. Rồi local.py chỉ cần ghi đè đúng những gì khác với môi trường local — ở đây chỉ 1 dòng: DEBUG = True. Đây là lý do repo có 4 file thay vì 1: mỗi môi trường (local/test/production) chỉ khai báo phần khác biệt, phần chung nằm hết ở base.py.

4. Cơ chế thật đằng sau from .base import *

Python thực thi base.py trước, tạo một namespace chứa mọi biến top-level của nó, rồi copy toàn bộ tên đó sang namespace của local.py. Vì vậy thứ tự quan trọng: import phải nằm trước DEBUG = True, nếu không dòng import sẽ đè ngược lại giá trị mặc định — đây chỉ là quy tắc gán biến bình thường của Python, không có gì đặc thù của Django.

Chú thích # noqa: F403 tắt cảnh báo linter về import * (khó biết biến đến từ đâu) — team chấp nhận đánh đổi này để không phải lặp lại toàn bộ base.py trong mỗi file môi trường.

5. env(...): đọc config từ .env, không hard-code

env("SECRET_KEY")                   # bat buoc co trong .env
env.bool("DEBUG", default=False)     # co gia tri mac dinh
env.db_url("DATABASE_URL")           # parse thanh dict ket noi DB

base.py được commit vào git và dùng chung mọi môi trường — hard-code secret vào đó nghĩa là ai đọc repo cũng đọc được secret. Đọc từ .env (không commit) tách "code" khỏi "cấu hình".

env là một object (environ.Env()), và env("SECRET_KEY") gọi được như hàm nhờ dunder method __call__ — cùng họ với __init__ bạn học ở bài 4. Bên trong, nó tìm SECRET_KEY trong os.environ (đã nạp từ .env) và trả về giá trị.

3 dòng ví dụ cho thấy 3 mức bắt buộc: env("SECRET_KEY") không có default nên bắt buộc có trong .env, thiếu sẽ raise lỗi ngay; env.bool(...) có default và tự ép kiểu bool từ chuỗi môi trường; env.db_url(...) parse connection string thành dict cho DATABASES["default"].
